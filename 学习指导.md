## 架构分层剖析与数据流动

### 主要分层
- **客户端/目标服务器**：发起和接收请求/响应。
- **ProxyServer**：负责监听端口、管理连接、分发数据到协议层。
- **协议层栈**（TCP/TLS/HTTP/WebSocket等）：按协议分层处理数据，支持多种协议的解包、加密、解密、重组。
- **Addons/Hooks**：插件和钩子系统，允许用户自定义流量处理逻辑。
- **Master/EventLoop**：全局事件循环，调度各层协作。

### 数据流动详细说明

#### HTTP/HTTPS流量
- 客户端请求 → ProxyServer → TCP层 → TLS层（如有）→ HTTP层 → 目标服务器
- 目标服务器响应 → HTTP层 → TLS层（如有）→ TCP层 → ProxyServer → 客户端

#### WebSocket流量
- 客户端发起HTTP Upgrade请求 → HTTP层识别升级 → WebSocket层接管
- WebSocket消息（双向）：
  - 客户端消息：WebSocket层解析 → 可被插件/钩子处理 → 转发到服务器
  - 服务器消息：WebSocket层解析 → 可被插件/钩子处理 → 转发到客户端
- 支持消息拦截、修改、注入、丢弃等操作

#### 插件/钩子处理
- 每一层（如HTTP、WebSocket）在关键事件（如请求、响应、消息到达）时，都会触发对应的钩子（request、response、websocket_message等）。
- 插件可对流量进行任意处理，如记录、修改、阻断、注入等。

## Sans-IO模式详解

### Sans-IO设计原理

Sans-IO（无I/O）模式是mitmproxy的核心设计模式，它将协议逻辑与I/O操作分离：

**优势**:

1. **可测试性** - 协议逻辑可以独立测试
2. **性能** - 避免阻塞操作，提高并发性能
3. **灵活性** - 可以在不同的I/O后端上运行
4. **调试性** - 事件和命令的明确分离便于调试

**工作流程**:

```
输入事件 → 协议层处理 → 输出命令 → I/O执行 → 新事件 → ...
```

### 协议层栈示例

```
HTTP Layer    ← 应用层协议
    ↓
TLS Layer     ← 安全层协议  
    ↓
TCP Layer     ← 传输层协议
    ↓
Network I/O   ← 实际网络操作
```

## 钩子系统详解 (mitmproxy/hooks.py)

### 主要钩子类型

```python
class Hook:
    """钩子基类"""

class RequestHook(Hook):
    """HTTP请求钩子 - 在发送到服务器前触发"""

class ResponseHook(Hook):
    """HTTP响应钩子 - 在发送到客户端前触发"""

class ServerConnectHook(Hook):
    """服务器连接钩子 - 在连接目标服务器时触发"""

class TlsClienthelloHook(Hook):
    """TLS客户端Hello钩子 - 在TLS握手开始时触发"""

class TlsEstablishedClientHook(Hook):
    """TLS建立钩子（客户端） - 在与客户端TLS握手完成时触发"""

class TlsEstablishedServerHook(Hook):
    """TLS建立钩子（服务器） - 在与服务器TLS握手完成时触发"""

class ErrorHook(Hook):
    """错误钩子 - 在发生错误时触发"""
```
