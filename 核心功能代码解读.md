## 1. 整体架构与数据流

### 1.1 架构分层

mitmproxy 采用分层架构，从底层到高层依次为：

```
┌─────────────────────────────────────┐
│  应用层 - Addons/Scripts/UI         │  ← 用户交互层
├─────────────────────────────────────┤
│  协议层 - HTTP/WebSocket/TCP        │  ← 应用协议处理
├─────────────────────────────────────┤
│  安全层 - TLS/SSL                   │  ← 加密传输处理
├─────────────────────────────────────┤
│  传输层 - TCP/UDP                   │  ← 基础传输协议
├─────────────────────────────────────┤
│  网络 I/O - asyncio                 │  ← 异步 I/O 操作
└─────────────────────────────────────┘
```

### 1.2 核心组件交互

```
Master (主控制器)
  ├── AddonManager (插件管理器)
  │     └── 各种 Addons (插件)
  ├── CommandManager (命令管理器)
  ├── Options (配置管理)
  └── ProxyServer (代理服务器)
        ├── ConnectionHandler (连接处理器)
        │     └── Context (连接上下文)
        └── Layer Stack (协议层栈)
              ├── HTTP Layer
              ├── TLS Layer
              └── TCP Layer
```

### 1.3 请求处理流程

```
客户端请求
  ↓
ProxyServer.handle_client()  -- 接收客户端连接
  ↓
ConnectionHandler.handle_connection()  -- 创建连接上下文
  ↓
Layer.handle_event()  -- 处理网络事件
  ↓ (产生命令)
Command execution  -- 执行命令（连接服务器、发送数据等）
  ↓ (产生新事件)
Addon hooks  -- 触发插件钩子（request、response等）
  ↓
发送响应给客户端
```

## 2. Master 主控制器详解

### 2.1 核心职责

**文件**: `mitmproxy/master.py`

Master 是 mitmproxy 的核心控制器，负责：
1. 初始化和管理所有子系统
2. 运行主事件循环
3. 协调插件、命令、选项等组件
4. 处理流量的加载和重放

### 2.2 初始化流程

```python
def __init__(self, opts, event_loop=None, with_termlog=False):
    # 1. 创建或使用提供的配置选项
    self.options = opts or options.Options()
    
    # 2. 创建命令管理器
    self.commands = command.CommandManager(self)
    
    # 3. 创建插件管理器
    self.addons = addonmanager.AddonManager(self)
    
    # 4. 可选：添加终端日志插件
    if with_termlog:
        self._termlog_addon = termlog.TermLog()
        self.addons.add(self._termlog_addon)
    
    # 5. 设置事件循环
    self.event_loop = event_loop or asyncio.get_running_loop()
    
    # 6. 创建退出信号
    self.should_exit = asyncio.Event()
    
    # 7. 设置全局上下文
    mitmproxy_ctx.master = self
    mitmproxy_ctx.options = self.options
```

**关键点**:
- Master 需要在已有的事件循环中创建，因为某些插件在初始化时就会创建异步任务
- `should_exit` 事件用于优雅关闭

### 2.3 主循环运行

```python
async def run(self) -> None:
    # 1. 安装异常处理器和 eager task factory
    with (
        asyncio_utils.install_exception_handler(self._asyncio_exception_handler),
        asyncio_utils.set_eager_task_factory(),
    ):
        self.should_exit.clear()
        
        # 2. 检查是否需要提前退出（错误检查）
        if ec := self.addons.get("errorcheck"):
            await ec.shutdown_if_errored()
        
        # 3. 启动代理服务器
        if ps := self.addons.get("proxyserver"):
            await asyncio.wait(
                [
                    asyncio_utils.create_task(ps.setup_servers(), ...),
                    asyncio_utils.create_task(self.should_exit.wait(), ...),
                ],
                return_when=asyncio.FIRST_COMPLETED,
            )
            if self.should_exit.is_set():
                return
        
        # 4. 触发 running 钩子
        await self.running()
        
        # 5. 等待退出信号
        await self.should_exit.wait()
        
        # 6. 触发 done 钩子并清理
        await self.done()
```

**设计亮点**:
- 使用 `asyncio.wait()` 同时监控服务器启动和退出信号
- 分阶段钩子触发：`running` → 正常运行 → `done`
- 异常处理器确保未捕获的异常被妥善处理

### 2.4 流量加载与重放

```python
async def load_flow(self, f):
    # 通过 eventsequence 模块按顺序触发流量事件
    for e in eventsequence.iterate(f):
        await self.addons.handle_lifecycle(e)
```

**实现细节**:
- `eventsequence.iterate()` 将流量对象转换为事件序列
- 事件按顺序触发插件钩子，模拟真实流量流程
- 支持 HTTP、TCP、WebSocket 等多种流量类型

## 3. 代理服务器实现

### 3.1 ProxyServer 架构

**文件**: `mitmproxy/proxy/server.py`

ProxyServer 是代理服务器的核心实现，负责：
1. 监听端口并接受客户端连接
2. 为每个连接创建 ConnectionHandler
3. 管理服务器的启动和关闭

### 3.2 ConnectionHandler 连接处理

```python
class ConnectionHandler:
    """
    处理单个客户端连接的完整生命周期
    """
    
    async def handle_client(self, client):
        # 1. 创建连接上下文
        context = Context(
            client=client,
            options=self.options,
            ...
        )
        
        # 2. 触发 client_connected 钩子
        await self.handle_hook(hooks.ClientConnectedHook(context.client))
        
        # 3. 处理连接
        await self.handle_connection(context)
        
        # 4. 触发 client_disconnected 钩子
        await self.handle_hook(hooks.ClientDisconnectedHook(context.client))
    
    async def handle_connection(self, context):
        # 1. 创建顶层协议层
        layer = self.make_top_layer(context)
        
        # 2. 创建超时监控器
        watchdog = TimeoutWatchdog(
            timeout=self.options.client_timeout,
            callback=lambda: self.close_connection(context.client)
        )
        
        # 3. Sans-IO 主循环
        while True:
            # 从网络读取数据 → 转换为事件
            event = await self.receive_event()
            
            # 重置超时
            watchdog.register_activity()
            
            # 协议层处理事件 → 产生命令
            for command in layer.handle_event(event):
                # 执行命令 → 产生新事件
                await self.execute_command(command)
```

**核心设计**:
- **Sans-IO 模式**: 协议逻辑与 I/O 操作完全分离
- **事件驱动**: 网络 I/O → 事件 → 协议层处理 → 命令 → I/O 执行
- **超时管理**: 通过 TimeoutWatchdog 监控连接活跃度

### 3.3 超时监控机制

```python
class TimeoutWatchdog:
    """
    监控连接超时，在指定时间内无活动则触发回调
    """
    
    def __init__(self, timeout: float, callback):
        self.timeout = timeout
        self.callback = callback
        self.last_activity = time.time()
        self._task = asyncio.create_task(self.watch())
    
    def register_activity(self):
        """记录活动，重置超时计时器"""
        self.last_activity = time.time()
    
    async def watch(self):
        """持续监控，超时则触发回调"""
        while True:
            await asyncio.sleep(1)
            if time.time() - self.last_activity > self.timeout:
                self.callback()
                break
    
    @contextmanager
    def disarm(self):
        """临时禁用超时（上下文管理器）"""
        # 在某些长时间操作时使用
        pass
```

## 4. Sans-IO 协议层架构

### 4.1 Sans-IO 设计模式

Sans-IO（无 I/O）是 mitmproxy 的核心设计模式，将协议逻辑与网络 I/O 完全解耦。

**优势**:
1. **可测试性**: 协议逻辑可以独立测试，无需模拟网络
2. **性能**: 避免阻塞操作，所有 I/O 都异步执行
3. **灵活性**: 同一协议实现可以在不同 I/O 后端上运行
4. **清晰性**: 事件和命令的明确分离使代码易于理解

### 4.2 Layer 基类

**文件**: `mitmproxy/proxy/layer.py`

```python
class Layer:
    """
    协议层基类，实现 Sans-IO 模式
    """
    
    def __init__(self, context: Context):
        self.context = context
        self.child_layer = None  # 可选的子层
    
    def handle_event(self, event: Event) -> CommandGenerator[None]:
        """
        处理输入事件，产生命令序列
        
        这是 Sans-IO 的核心方法：
        - 输入：网络事件（数据接收、连接建立等）
        - 输出：命令序列（发送数据、建立连接等）
        """
        # 调用子类的具体实现
        for command in self._handle_event(event):
            yield command
    
    def _handle_event(self, event: Event) -> CommandGenerator[None]:
        """
        子类实现的具体事件处理逻辑
        """
        raise NotImplementedError()
```

### 4.3 协议层栈

协议层可以嵌套形成协议栈：

```
┌──────────────────────┐
│   HTTP Layer         │  ← 解析 HTTP 请求/响应
├──────────────────────┤
│   TLS Layer          │  ← 处理 TLS 加密/解密
├──────────────────────┤
│   TCP Layer          │  ← 管理 TCP 连接和数据传输
└──────────────────────┘
         ↓↑
    网络 I/O
```

**实现方式**:
```python
# HTTP Layer 包含 TLS Layer 作为子层
http_layer = HttpLayer(context)
http_layer.child_layer = TlsLayer(context)
http_layer.child_layer.child_layer = TcpLayer(context)
```

### 4.4 事件流转示例

```python
# 1. 网络接收到数据
data_received_event = DataReceived(connection=client, data=b"GET / HTTP/1.1\r\n...")

# 2. HTTP Layer 处理事件
for command in http_layer.handle_event(data_received_event):
    if isinstance(command, SendData):
        # 3. 执行发送数据命令
        await connection.send(command.data)
    elif isinstance(command, RequestHook):
        # 4. 触发请求钩子
        await addons.trigger(command.flow)
```

## 5. 事件与命令系统

### 5.1 事件类型

**文件**: `mitmproxy/proxy/events.py`

事件表示网络层发生的事情，由 I/O 层产生，交给协议层处理。

```python
@dataclass
class Event:
    """事件基类"""
    pass

@dataclass
class DataReceived(Event):
    """接收到数据"""
    connection: Connection
    data: bytes

@dataclass
class ConnectionClosed(Event):
    """连接关闭"""
    connection: Connection

@dataclass
class Start(Event):
    """层启动（初始事件）"""
    pass
```

**完整事件列表**:
- `Start`: 协议层启动
- `DataReceived`: 接收到数据
- `ConnectionClosed`: 连接关闭
- `CommandCompleted`: 命令执行完成
- `CommandReply`: 命令的回复（如握手结果）

### 5.2 命令类型

**文件**: `mitmproxy/proxy/commands.py`

命令表示协议层想要执行的操作，由协议层产生，交给 I/O 层执行。

```python
@dataclass
class Command:
    """命令基类"""
    pass

@dataclass
class SendData(Command):
    """发送数据"""
    connection: Connection
    data: bytes

@dataclass
class OpenConnection(Command):
    """打开到服务器的连接"""
    connection: Server

@dataclass
class CloseConnection(Command):
    """关闭连接"""
    connection: Connection
    half_close: bool = False  # 半关闭（只关闭写端）
```

**完整命令列表**:
- `SendData`: 发送数据
- `OpenConnection`: 建立连接
- `CloseConnection`: 关闭连接
- `RequestHook`: 触发请求钩子
- `ResponseHook`: 触发响应钩子
- `StartTls`: 启动 TLS 握手
- `GetSocket`: 获取底层 socket（用于外部处理）

### 5.3 事件-命令循环

```
┌─────────┐     事件     ┌──────────┐     命令     ┌─────────┐
│ I/O 层  │ ──────────→ │ 协议层    │ ──────────→ │ I/O 层  │
│(网络)   │ ←────────── │ (逻辑)    │ ←────────── │(执行)   │
└─────────┘   新事件     └──────────┘   命令结果   └─────────┘
```

**示例流程**:
```python
# 客户端发送 CONNECT 请求
event = DataReceived(client, b"CONNECT example.com:443 HTTP/1.1\r\n...")

# HTTP Layer 解析并产生命令
commands = http_layer.handle_event(event)
# → [OpenConnection(server), SendData(client, "200 OK")]

# I/O 执行命令
await server.connect()
await client.send(b"HTTP/1.1 200 OK\r\n\r\n")

# 产生新事件
event = ConnectionOpened(server)
```

### 6.3 连接池管理

mitmproxy 实现了连接复用来提高性能：

```python
class ConnectionPool:
    """
    管理到目标服务器的连接池
    """
    
    def __init__(self):
        self.connections = {}  # (host, port) → [Server]
    
    def get_connection(self, host: str, port: int) -> Server | None:
        """获取可复用的连接"""
        key = (host, port)
        if key in self.connections:
            # 检查连接是否仍然有效
            for conn in self.connections[key]:
                if conn.state == ConnectionState.OPEN:
                    return conn
        return None
    
    def add_connection(self, server: Server):
        """添加连接到池中"""
        key = (server.address[0], server.address[1])
        if key not in self.connections:
            self.connections[key] = []
        self.connections[key].append(server)
```

### 7.2 证书生成与管理

**文件**: `mitmproxy/certs.py`

```python
class CertStore:
    """
    证书存储，管理 CA 和伪造的服务器证书
    """
    
    def __init__(self, ca: Cert):
        self.ca = ca  # 根 CA 证书
        self.certs = {}  # 缓存生成的证书
    
    def get_cert(self, commonname: str, sans: list[str]) -> Cert:
        """
        获取或生成指定域名的证书
        
        流程：
        1. 检查缓存中是否有该域名的证书
        2. 如果没有，使用 CA 签发新证书
        3. 证书包含所有 SANs（主题替代名称）
        4. 缓存证书供后续使用
        """
        key = (commonname, tuple(sorted(sans)))
        if key not in self.certs:
            self.certs[key] = dummy_cert(
                privkey=self.ca.private_key,
                cacert=self.ca.cert,
                commonname=commonname,
                sans=sans,
            )
        return self.certs[key]

def dummy_cert(privkey, cacert, commonname, sans):
    """
    生成伪造的服务器证书
    
    参数：
    - privkey: CA 私钥
    - cacert: CA 证书
    - commonname: 证书通用名（通常是域名）
    - sans: 主题替代名称列表
    
    返回：
    - 使用 CA 签名的服务器证书
    """
    # 1. 创建新证书
    cert = crypto.X509()
    
    # 2. 设置版本和序列号
    cert.set_version(2)
    cert.set_serial_number(int(uuid.uuid4().hex[:16], 16))
    
    # 3. 设置主体信息
    cert.get_subject().CN = commonname
    
    # 4. 添加 SANs 扩展
    san_list = [f"DNS:{name}" for name in sans]
    cert.add_extensions([
        crypto.X509Extension(
            b"subjectAltName",
            False,
            ", ".join(san_list).encode()
        )
    ])
    
    # 5. 设置有效期（365天）
    cert.gmtime_adj_notBefore(0)
    cert.gmtime_adj_notAfter(365 * 24 * 60 * 60)
    
    # 6. 使用 CA 签名
    cert.set_issuer(cacert.get_subject())
    cert.sign(privkey, "sha256")
    
    return Cert(cert)
```

### 7.3 TLS Layer 实现

```python
class TlsLayer(Layer):
    """
    TLS/SSL 协议层
    """
    
    def __init__(self, context: Context):
        super().__init__(context)
        self.tls_started = False
        self.client_hello = None
    
    def _handle_event(self, event: Event) -> CommandGenerator:
        if isinstance(event, DataReceived):
            if not self.tls_started:
                # 解析 ClientHello
                self.client_hello = parse_client_hello(event.data)
                
                # 提取 SNI（Server Name Indication）
                sni = self.client_hello.sni or self.context.server.address[0]
                
                # 触发 tls_clienthello 钩子
                yield RequestHook(TlsClienthelloHook(self.context, self.client_hello))
                
                # 生成服务器证书
                cert = self.context.options.certstore.get_cert(
                    commonname=sni,
                    sans=[sni]
                )
                
                # 启动 TLS 握手
                yield StartTls(
                    connection=self.context.client,
                    cert=cert
                )
                
                self.tls_started = True
            else:
                # TLS 已建立，传递加密数据给子层
                yield from self.child_layer.handle_event(event)
```

### 8.1 HTTP Layer 架构

**文件**: `mitmproxy/proxy/layers/http/http.py`

```python
class HttpLayer(Layer):
    """
    HTTP 协议层，支持 HTTP/1.1 和 HTTP/2
    """
    
    def __init__(self, context: Context):
        super().__init__(context)
        self.flows = {}  # stream_id → HTTPFlow
        self.mode = None  # 将通过检测确定是 HTTP/1 还是 HTTP/2
    
    def _handle_event(self, event: Event) -> CommandGenerator:
        if isinstance(event, DataReceived):
            # 检测 HTTP 版本
            if self.mode is None:
                self.mode = self.detect_http_version(event.data)
            
            # 委托给具体的 HTTP 版本处理器
            if self.mode == "http/1.1":
                yield from self.handle_http1(event)
            elif self.mode == "http/2":
                yield from self.handle_http2(event)
```

### 8.2 HTTP/1.1 处理

```python
class Http1Layer(HttpLayer):
    """HTTP/1.1 处理器"""
    
    def __init__(self, context: Context):
        super().__init__(context)
        self.request_parser = Http1RequestParser()
        self.response_parser = Http1ResponseParser()
    
    def handle_http1(self, event: DataReceived) -> CommandGenerator:
        # 1. 解析请求
        if event.connection == self.context.client:
            try:
                request = self.request_parser.parse(event.data)
            except ValueError as e:
                yield SendData(event.connection, b"HTTP/1.1 400 Bad Request\r\n\r\n")
                yield CloseConnection(event.connection)
                return
            
            # 2. 创建 Flow 对象
            flow = http.HTTPFlow(self.context.client, self.context.server)
            flow.request = request
            
            # 3. 触发 request 钩子
            yield RequestHook(flow)
            
            # 4. 检查是否需要转发到服务器
            if flow.response is None:
                # 打开服务器连接
                if self.context.server.state != ConnectionState.OPEN:
                    yield OpenConnection(self.context.server)
                
                # 发送请求到服务器
                yield SendData(self.context.server, bytes(request))
        
        # 5. 解析响应
        elif event.connection == self.context.server:
            response = self.response_parser.parse(event.data)
            flow.response = response
            
            # 6. 触发 response 钩子
            yield ResponseHook(flow)
            
            # 7. 发送响应到客户端
            yield SendData(self.context.client, bytes(response))
```

### 8.4 流式处理

mitmproxy 支持流式处理大型响应体：

```python
class StreamingResponse:
    """
    流式响应处理
    
    用于处理大文件或长时间响应，避免内存占用过大
    """
    
    def __init__(self, flow: HTTPFlow):
        self.flow = flow
        self.chunks = []
    
    async def stream_response(self):
        """
        流式接收和转发响应
        """
        # 1. 接收响应头
        headers = await self.receive_headers()
        
        # 2. 立即发送响应头给客户端
        await self.send_headers(headers)
        
        # 3. 流式转发响应体
        async for chunk in self.receive_chunks():
            # 可选：修改 chunk（但要小心）
            modified_chunk = self.modify_chunk(chunk)
            await self.send_chunk(modified_chunk)
        
        # 4. 发送尾部头（如果有）
        if trailers := await self.receive_trailers():
            await self.send_trailers(trailers)
```

### 9.1 插件管理器

**文件**: `mitmproxy/addonmanager.py`

```python
class AddonManager:
    """
    管理所有插件的生命周期和钩子触发
    """
    
    def __init__(self, master):
        self.master = master
        self.addons = []  # 已加载的插件列表
        self.hooks = defaultdict(list)  # 钩子名称 → 处理函数列表
    
    def add(self, addon):
        """
        添加插件
        
        步骤：
        1. 将插件添加到列表
        2. 扫描插件的方法，注册钩子处理函数
        3. 调用插件的 load() 方法（如果有）
        """
        self.addons.append(addon)
        
        # 注册钩子
        for name in dir(addon):
            if name in hooks.HOOKS:
                method = getattr(addon, name)
                self.hooks[name].append(method)
        
        # 调用 load 钩子
        if hasattr(addon, 'load'):
            addon.load(self.master)
    
    async def trigger(self, name: str, *args, **kwargs):
        """
        触发指定钩子
        
        按顺序调用所有注册了该钩子的插件方法
        """
        for method in self.hooks[name]:
            try:
                result = method(*args, **kwargs)
                # 如果方法是协程，等待其完成
                if asyncio.iscoroutine(result):
                    await result
            except Exception as e:
                logger.error(f"Error in hook {name}: {e}")
```

```python
class CustomAddon:

    自定义插件示例
    """

        self.num_requests = 0
    
    def load(self, loader):
        """

        - 添加自定义选项
        - 注册命令
        - 初始化资源

            name="custom_header",
            typespec=str,
            default="",
            help="自定义头部值"
        )
    
    def request(self, flow: http.HTTPFlow):
        """
        处理 HTTP 请求
        
        在请求发送到服务器之前调用
        """
        self.num_requests += 1
        
        # 修改请求
        if self.options.custom_header:
            flow.request.headers["X-Custom"] = self.options.custom_header
        
        # 阻止请求（直接返回响应）
        if flow.request.path == "/blocked":
            flow.response = http.Response.make(
                status_code=403,
                content=b"Blocked by mitmproxy",
                headers={"Content-Type": "text/plain"}
            )
    
    def response(self, flow: http.HTTPFlow):
        """
        处理 HTTP 响应
        
        在响应发送到客户端之前调用
        """
        # 记录信息
        print(f"Response {flow.response.status_code} for {flow.request.url}")
        
        # 修改响应
        if "text/html" in flow.response.headers.get("content-type", ""):
            flow.response.content = flow.response.content.replace(
                b"</body>",
                b"<script>console.log('Injected by mitmproxy')</script></body>"
            )
    
    def server_connect(self, data: ServerConnectionHookData):
        """
        连接服务器前调用
        
        可以修改目标地址或连接参数
        """
        # 重定向到不同服务器
        if data.server.address[0] == "example.com":
            data.server.address = ("different-server.com", 443)
    
    async def done(self):
        """
        插件卸载时调用
        
        清理资源、保存状态等
        """
        print(f"Total requests processed: {self.num_requests}")

# 注册插件
addons = [CustomAddon()]
```

```python
class Flow:
    """
    流量基类
    
    表示一次完整的网络会话
    """
    
    def __init__(self, client: Client, server: Server):
        self.id = str(uuid.uuid4())
        self.client_conn = client
        self.server_conn = server
        self.error = None
        self.intercepted = False
        self.marked = False
        self.metadata = {}
        self.comment = ""
        self.backup = None
        self.reply = None
    
    def copy(self):
        """深拷贝流量对象"""
        return copy.deepcopy(self)
    
    def backup(self):
        """备份当前状态（用于恢复）"""
        self.backup = self.copy()
    
    def revert(self):
        """恢复到备份状态"""
        if self.backup:
            self.__dict__.update(self.backup.__dict__)
```

```python
class HTTPFlow(Flow):
    """
    HTTP 流量对象
    
    表示一次完整的 HTTP 请求-响应
    """
    
    request: Request
    response: Response | None = None
    websocket: WebSocketData | None = None  # 如果升级到 WebSocket
    
    # 时间戳
    timestamp_created: float = field(default_factory=time.time)
    
    # 模式相关
    mode: str = "regular"  # regular, transparent, reverse, upstream
    
    @property
    def timestamp_start(self) -> float:
        """流量开始时间"""
        return self.request.timestamp_start
    
    @property
    def timestamp_end(self) -> float | None:
        """流量结束时间"""
        if self.response:
            return self.response.timestamp_end
        return None
```
